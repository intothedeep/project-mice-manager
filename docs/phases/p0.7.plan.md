- **Punch records + mouse-identity label composition (architect design
  2026-09-16 — GATED on §5 Q39–Q45; steps in TASKS P0.7-b):** a mouse is
  physically identified by PUNCHES, tracked as RECORDS, not a field.
  - **Table `punches` (migration `0026_punches.sql`; 0025 = current highest):**
    `id`, `mouse_id` → **`mouse_meta(id)`** (NOT `mice`, which holds version
    rows), `punch_location TEXT CHECK IN ('toe','ear','other')`,
    `effective_at` (when the punch physically happened — DISTINCT from
    `created_at` = tx-start time), `actor_id` → `users(id)`, `note`,
    `created_at`, `updated_at`, `deleted_at`. Partial index `(mouse_id) WHERE
    deleted_at IS NULL`. NO UNIQUE on (mouse_id, location). NO DB trigger.
    Add = INSERT; remove = `deleted_at` (§22.4 soft-delete).
  - **Creating a mouse mints an implicit `toe` punch — in `addMouse` and
    NOWHERE else.** `addMouse` is the sole `metaId` allocator, so
    once-and-only-once is structural. NOT a trigger: a future import path must
    not double-write it.
  - **Label = read-time projection (EXTENDS, does not replace, the P0-b rule
    `renderedId = head.sex + pup_number + litter_code`).** `toe` renders NO
    suffix; `ear` renders `e`. New pure `lib/mouseIdentity.ts`
    `buildMouseLabel(...)` (spec'd as `composeMouseIdentity`) composes `sex · pupNumber · [+offset] ·
    litterCode · [e]`; `.N` stays outermost in `composeMouseLabel`.
    SUPERSEDED 2026-09-16 (Q39 RESOLVED): there is no `earSuffixPosition`
    parameter — the mid position is abolished, `e` is always tail, and
    "transferred THEN tagged" renders as a DERIVED COLOUR on the `e`. Compose
    emits tail only; PARSE must still accept the legacy/hand-written mid form.
    Pure
    `lib/punchMutations.ts` `addPunch`/`removePunch` is a NEW module (NOT in

    `punches: PunchRef[]` (active rows only) and NO stored label.
    `pup_number` needs NO `side`/`count` on the punch record — Q11 (resolved
    2026-09-04) ruled it carries no orderable or tag-location meaning.
